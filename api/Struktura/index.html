Struktura

A lightweight services/controllers framework with a small networking surface. Struktura is designed around two module "roles":

  • Services (server): any module that does not set Type == "Controller"
  • Controllers (client): modules that set Type == "Controller" Typical boot flow: 
local Struktura = require(ReplicatedStorage.Packages.Struktura)
-- Server
Struktura.Initialize(ServerScriptService.Services, true)
Struktura.Start():catch(warn)
-- Client
Struktura.Initialize(Players.LocalPlayer.PlayerScripts.Controllers, true)
Struktura.Start():catch(warn)

Lifecycle

Modules may optionally implement Init (runs before Start resolves) and Start (runs after). Struktura also forwards a small set of lifecycle events to modules as On<EventName> methods:

  • OnPlayerAdded(player)
  • OnPlayerRemoving(player)
  • OnCharacterAdded(player, character)
  • OnBindToClose(reason) (server only) You can define your own lifecycle events with Struktura.CreateLifecycle.

Service client surface

Services can expose a Client table. Functions inside Client become RPC handlers callable from the client. To expose server → client signals, assign a field to the marker returned by [Struktura.CreateSignal]: 

local Struktura = require(ReplicatedStorage.Packages.Struktura)
local MyService = { Name = "MyService" }
MyService.Client = {
    DataChanged = Struktura.CreateSignal(),
    GetData = function(self, player) return {} end,
}
return MyService

On the client, use Struktura.GetService to access these methods and signals.

Types​

PlayerName​

</>
type PlayerName = string

Convenience alias for Player.Name when using the framework APIs.

Target​

</>
type Target = Player | PlayerName | {PlayerName} | "All" | {Except: PlayerName} | nil

The set of supported target formats for server → client signals.

  • Player: fire to a specific player
  • PlayerName / { PlayerName }: fire to one or more players by name
  • "All": fire to every player
  • { Except = PlayerName }: fire to everyone except one player name
  • nil: an implementation-defined default (see Net)

Functions​

Configure​

</>
Struktura.Configure(
options: Settings?--

Configuration overrides.

) → ()

Configures Struktura runtime options. This is usually called once during boot, before Struktura.Start. ServicePromises controls how client-side service method calls behave:

  • true (default): methods return a Promise-like object from Net:Request(...)
  • false: methods synchronously :await() the request and return the result (this yields)

CreateLifecycle​

</>
Struktura.CreateLifecycle(
name: string,--

Lifecycle name (without the On prefix).

signal: EventSignal--

Any object with :Connect(callback) that returns a disconnectable connection.

) → PromiseLike--

Resolves when the lifecycle is registered; rejects if it already exists.

Creates and (optionally) binds a custom lifecycle event. Once created, any module can listen by implementing a method named On<name>. For example, if you create a lifecycle named "RoundStarted", modules may implement OnRoundStarted(...). If Struktura has already started (or is in the process of starting), the lifecycle is bound immediately. Otherwise, it will be bound during Struktura.Start.

CreateSignal​

This item only works when running on the server. Server
</>
Struktura.CreateSignal() → any--

The internal marker object.

Creates a signal marker for use inside a service's Client table (server only). This does not create a real Signal object. Instead, it returns an opaque marker used by Struktura during Struktura.Start to convert the field into a server signal wrapper (see ServerSignal). Example: 

local MyService = { Name = "MyService" }
MyService.Client = {
    Pinged = Struktura.CreateSignal(),
}
function MyService:Start()
    self.Client.Pinged:FireAll("hello")
end

OnStart​

This is a yielding function. When called, it will pause the Lua thread that called the function until a result is ready to be returned, without interrupting other scripts. Yields
</>
Struktura.OnStart() → PromiseLike

Returns a promise that resolves once Struktura has finished starting. This is useful when a controller wants to wait until all Init functions have run and services have been surfaced on the server.

Initialize​

</>
Struktura.Initialize(
container: Folder,--

Folder containing modules.

deep: boolean?--

Whether to include descendants.

) → PromiseLike--

Resolves with a timing string when initialization completes.

Loads (requires) modules from a container folder and registers them with Struktura.

  • If deep is truthy, Struktura scans all descendants; otherwise it only scans direct children.
  • Any module that returns a table is registered.
  • If that table has Type == "Controller", it's treated as a controller (client). Otherwise it's a service (server). You must call this before Struktura.Start if you want modules to participate in lifecycle events.

GetController​

This item only works when running on the client. Client
</>
Struktura.GetController(
name: string--

Controller name.

) → T?--

The controller table if found, otherwise nil.

Returns a previously-initialized controller by name (client only). Controllers are registered during Struktura.Initialize. Names come from the returned table's Name field or fall back to the ModuleScript name.

</>
Struktura.GetService(
name: string--

Service name.

) → T--

Service table (server) or proxy (client).

Returns a service by name. Behavior differs by realm:

  • Server: returns the raw service module table that was loaded during Struktura.Initialize.
  • Client: builds and caches a proxy based on server-provided metadata. The client proxy exposes:
  • Signal fields as objects with :Connect(callback)
  • Method calls via Service:MethodName(...) (implemented through __index) By default, calling a method returns a Promise-like value. You can change this with Struktura.Configure.

Start​

This item only works when running on the client. ClientThis item only works when running on the server. ServerThis is a yielding function. When called, it will pause the Lua thread that called the function until a result is ready to be returned, without interrupting other scripts. Yields
</>
Struktura.Start() → PromiseLike--

Resolves with a timing string when initialization hooks complete.

Starts Struktura: binds lifecycle events, starts networking, and runs module Init/Start hooks. Start order:

  1. Ensures Net is started
  2. Binds lifecycle signals (built-in and custom)
  3. Runs Init on every loaded module (services on server, controllers on client)
  4. On server, surfaces service Client tables (RPC + signals)
  5. Marks Struktura as started and then runs Start for each module asynchronously On the client, Struktura will wait for the server to set the ServerReady attribute before continuing.
